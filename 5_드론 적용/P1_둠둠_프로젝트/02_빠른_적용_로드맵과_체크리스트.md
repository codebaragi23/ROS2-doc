## 1. 개요

[[01_통합_노드_아키텍처|01]]에서 그린 전체 구조를 처음부터 한 번에 구현하고 실기체로 검증하는 것은 리스크가 크다. 이 문서는 **"무엇을 먼저 검증하고, 각 단계를 넘어가는 기준이 무엇인가"**를 순서대로 정리한다. 원칙은 하나다 — **실기체 비행은 최대한 늦게, 그 전에 검증 가능한 건 전부 지상/SITL에서 끝낸다**([[05_안전과_실전_고려사항|드론 적용 05]] "시뮬레이션 우선 원칙"과 동일).

## 2. 핵심 개념: 단계(Phase)별 로드맵

각 Phase는 **이전 Phase가 통과 조건을 만족해야 시작**한다. 실기체 비행은 Phase 5부터다 — 그 전 네 단계는 전부 지상/SITL/오프라인 재생으로 끝낸다.

### Phase 0 — Offboard 제어 기본기 (SITL, LIO 없음)

FAST-LIO2나 실제 센서 없이, **PX4 SITL만으로 Offboard 제어와 정지 시맨틱**([[05_정지_회피와_setpoint_처리|05]])을 먼저 익힌다.

- [ ] SITL(Gazebo) 실행, `MicroXRCEAgent` 연결, `ros2 topic list`에 `/fmu/...` 토픽 확인
- [ ] `OffboardControlMode` + `TrajectorySetpoint` 스트리밍(20Hz+) → Offboard 모드 진입 성공
- [ ] Position setpoint로 단순 이동 → 목표 지점 도달 확인
- [ ] Velocity setpoint로 정지(velocity=0 유지) → 제자리 호버링 확인
- [ ] setpoint 스트림을 의도적으로 끊어봄 → `COM_OBL_RC_ACT=Hold` 설정대로 그 자리에서 호버링하는지 확인

**통과 조건**: 실제 좌표를 몰라도, "이 노드가 setpoint를 보내면 드론(SITL)이 그 의도대로 움직인다"를 신뢰할 수 있는 상태.

### Phase 1 — FAST-LIO2 단독 검증 (핸드헬드 또는 지상 이동, 비행 없음)

LiDAR+IMU를 손에 들거나 지상로봇(Yahboom)에 얹어 사무실을 한 바퀴 돌며 FAST-LIO2 odometry만 확인한다. **아직 루프클로저도, FC 연동도 없다.**

- [ ] FAST-LIO2가 ROS2에서 정상 빌드·실행됨([[03_FAST-LIO2_생태계와_맵_관리|03]] 참고)
- [ ] 정지 상태에서 odometry가 표류하지 않음(진동/전기적 노이즈 확인)
- [ ] 걸어서 한 바퀴 돌아 시작점 복귀 — 루프클로저 없이 odometry만으로 시작점과 끝점의 어긋남(드리프트) 크기를 실측하고 기록
- [ ] point cloud 밀도가 벽/문틀 형상을 알아볼 수 있는 수준인지 RViz로 확인

**통과 조건**: 드리프트 크기가 사무실 규모(약 10m) 대비 합리적인 수준(수십 cm 이내)이고, point cloud가 시각적으로 이해 가능한 형태로 쌓인다.

### Phase 2 — 매핑 모드 완성 (핸드헬드, 비행 없음)

[[01_통합_노드_아키텍처|01]] 3.1절의 매핑 모드(루프클로저 + 맵 저장)를 추가한다.

- [ ] 루프클로저 노드가 시작점 재방문 시 정상 발동함을 확인
- [ ] 저장된 맵(.pcd)을 열어 벽이 이중으로 겹쳐 보이지 않는지 확인(겹쳐 보이면 루프클로저 실패 또는 오탐)
- [ ] 사무실을 여러 각도로(왕복, 회전하며) 훑어 다각도 커버리지 확보 — 이유는 [[03_FAST-LIO2_생태계와_맵_관리|03]] 3장

**통과 조건**: 사무실 전체가 하나의 일관된 맵으로 저장되고, 여러 각도에서 훑은 지점들이 지도상 제자리에 맞아떨어진다.

### Phase 3 — 재위치 레이어 검증 (오프라인 재생, 비행 없음)

Phase 2에서 만든 맵에 대해, **별도로 녹화한 두 번째 주행 bag**을 재위치 레이어에 흘려보내 오프라인으로 검증한다.

- [ ] arm 시점 시뮬레이션(bag 재생 시작점) → 전역 재위치가 일정 시간 내 수렴하는지 확인, 수렴 시간 기록
- [ ] Phase 2와 다른 시작 위치/각도로 재생 → 재위치 강건성 확인(편도 1회 스캔만으로는 실패하기 쉬움 — [[03_FAST-LIO2_생태계와_맵_관리\|03]] 3장 참고)
- [ ] 재생 내내 지속 재위치(scan-to-map)가 주기적으로 `map→odom`을 갱신하는지 확인 — 1회성 보정에 그치지 않아야 함
- [ ] **의도적으로 재위치가 실패하는 상황**(전혀 다른 장소의 bag 등)을 넣어, [[04_재위치_레이어와_map_odom_보정|04]]의 안전 상태머신(hover 유지, 미확정 상태에서 이동 안 함)이 실제로 동작하는지 확인

**통과 조건**: 정상 케이스에서 재위치가 안정적으로 수렴하고, 실패 케이스에서 "모르는 채로 움직이는" 위험한 상태가 발생하지 않는다.

### Phase 4 — FC 통합 (지상 벤치, 비행 없음)

드론 기체 위에서, **아직 이륙하지 않은 채로** FAST-LIO2 + 재위치 + FC 연동을 전부 연결한다.

- [ ] FAST-LIO2 odometry를 PX4 EKF2에 external vision으로 공급 — 수신·좌표계 정합 확인([[04_재위치_레이어와_map_odom_보정|04]] 참고)
- [ ] `map→odom→base_link` TF 트리가 정상 구성됨을 `ros2 run tf2_tools view_frames`로 확인
- [ ] 기체를 손으로 들고 흔들며 odometry/재위치가 실제 움직임을 반영하는지 확인
- [ ] Phase 0에서 검증한 Offboard/setpoint 스트리밍이 이 통합 상태에서도 여전히 정상 동작하는지 재확인(노드 수가 늘어나며 CPU 부하로 주기가 밀리지 않는지)

**통과 조건**: 실제 기체 위에서 SLAM→FC→setpoint 전체 체인이 논리적으로 끊김 없이 연결됨을 확인했다(단, 아직 뜨지 않았다).

### Phase 5 — 첫 실비행: 매핑 모드만 (실기체)

**여기서부터 실제로 뜬다.** 목줄(테더)이나 낮은 고도, 사람이 옆에서 즉시 개입 가능한 조건에서 시작한다.

- [ ] [[05_안전과_실전_고려사항|드론 적용 - 05. 안전과 실전 고려사항]]의 실전 체크리스트를 전부 통과
- [ ] 짧은 직선 왕복 → 정지 → 착륙(가장 단순한 비행)부터 시작
- [ ] 문제 없으면 Phase 2와 같은 매핑 주행을 실비행으로 재현
- [ ] 비행 중 얻은 맵을 Phase 2의 핸드헬드 맵과 비교(진동·기체 흔들림이 매핑 품질에 주는 영향 확인)

### Phase 6 — 두 번째 실비행: 재위치 + 목표 주행 (실기체)

- [ ] Phase 5에서 만든 맵으로 재위치 모드 arm
- [ ] 짧은 거리(1~2m)의 단순 목표부터 시작 → 점진적으로 목표 거리/복잡도 확대
- [ ] [[05_정지_회피와_setpoint_처리|05]]의 로컬 회피가 실제 장애물(사람, 의자 등 안전하게 배치한 물체)에 반응하는지 확인

### Phase 7 (선택, 이후 확장) — 자동 탐색

[[06_자동_탐색_매핑과_확장_고려사항|06]] 참고. Phase 6까지 안정화된 뒤에만 착수한다.

## 3. 핵심 개념: 왜 이 순서인가

- **Phase 0~4가 전부 "비행 없음"**인 이유: 지상로봇과 달리 드론은 실패의 대가가 "정지"가 아니라 "추락"이다([[05_안전과_실전_고려사항|드론 적용 05]] 1장). SLAM·재위치·FC연동 로직의 버그는 대부분 비행 없이도 발견할 수 있으므로, 비행 전에 최대한 걸러낸다.
- **매핑을 재위치보다 먼저 완성**하는 이유: 재위치는 "좋은 맵이 있다"는 전제 위에서만 의미 있는 검증이 된다. 맵 품질이 나쁜 상태에서 재위치를 튜닝하면 원인이 맵인지 재위치 알고리즘인지 구분이 안 된다.
- **오프라인 재생(Phase 3)을 실비행 전에 넣는 이유**: 재위치 실패 케이스를 실비행에서 처음 겪는 것은 위험하다. bag 재생은 몇 번이고 안전하게 반복할 수 있다.

## 4. 진단 관점

| 증상 | 의심할 Phase |
|---|---|
| SITL에서 Offboard 진입 자체가 안 됨 | Phase 0 — LIO/재위치와 무관한 순수 FC 연동 문제 |
| 실기체에서만 odometry가 흔들림 | Phase 1은 통과했지만 실기체 진동/전기 노이즈가 새 변수 — Phase 4·5 사이의 갭 |
| 맵은 좋은데 재위치가 안 됨 | Phase 3의 오프라인 검증을 건너뛰었을 가능성 — 지금이라도 오프라인으로 원인 분리 |
| 지상에서는 다 되는데 뜨자마자 이상함 | Phase 4와 5 사이의 진동/전력/CPU 부하 차이 — [[05_안전과_실전_고려사항\|드론 적용 05]] 진단표 참고 |
