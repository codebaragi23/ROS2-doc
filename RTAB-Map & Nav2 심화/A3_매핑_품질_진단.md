# A3. 매핑 품질 진단

> RTAB-Map & Nav2 심화 시리즈 · Part A. 지도제작
> 이전 문서: A2. 매핑 실행 파이프라인과 핵심 파라미터

## 1. 개요

매핑을 마쳤는데 지도가 어긋나 있거나 loop closure가 잘 안 되는 경우, 어디서부터 원인을 찾아야 하는지 정리한다. Part B(Nav2)로 넘어가기 전 마지막 매핑 문서다.

## 2. 핵심 개념: Loop Closure 실패의 3대 원인

1. **센서 동기화 문제** — RGB-D 타임스탬프 불일치로 특징점 매칭 자체가 틀어짐 (A2에서 다룬 `rgbd_sync` 안정성과 직결)
2. **이동 속도 과다** — 특히 회전 시 빠르면 모션 블러로 Visual Odometry가 프레임 추적을 잃음
3. **임계값 미조정** — `Vis/MinInliers`, `Rtabmap/LoopThr`가 실내 조명·텍스처 환경과 맞지 않아 loop closure 자체를 건너뜀

## 3. 이 프로젝트에서의 적용 (Yahboom X3)

과거 진단에서 다음이 확인되었다([[ros2-nav-yahboom]] 참고):

- RealSense 드라이버가 CPU를 과점유하면 `rgbd_sync`의 프레임이 불안정해지고, 이는 곧 위 1번 원인(센서 동기화 문제)으로 이어진다. 즉 파라미터 튜닝 이전에 **드라이버 리소스 사용량 점검**이 우선이다.
- LiDAR 후방 사각지대 문제(각도 파라미터 제한 + 물리적 마운트 위치)가 있었고, 이를 해결해 360도 커버리지를 확보했다. LiDAR 커버리지가 부족하면 ICP 기반 loop closure 후보 자체가 줄어든다.

## 4. 재매핑 체크리스트

순서가 중요하다.

1. **조명 고정** — 형광등 점멸, 자연광 변화를 최소화한다. Loop closure는 조명 변화에 민감하다.
2. **속도 제한** — 회전 시 한 번에 큰 각도로 돌지 않는다 (모션 블러 방지).
3. **경로 설계** — 매핑 시작점 = 종료점이 되도록 경로를 짜서 자연스러운 loop 형성을 유도한다.
4. **겹침 확보** — 새 구역 진입 시 이미 매핑된 영역을 20% 이상 겹쳐서 주행한다.
5. **완료 후 후처리** — `detect_more_loop_closures` 서비스로 놓친 loop closure를 추가 탐색한다.

```bash
# 추가 loop closure 탐색
ros2 service call /rtabmap/detect_more_loop_closures \
  rtabmap_msgs/srv/DetectMoreLoopClosures {}

# 전역 그래프 재최적화
ros2 service call /rtabmap/global_bundle_adjustment \
  rtabmap_msgs/srv/GlobalBundleAdjustment {}
```

## 5. 진단 관점 (증상별)

| 증상 | 의심 원인 | 확인 방법 |
|---|---|---|
| 지도가 이중으로 겹침 | 같은 장소를 다른 노드로 인식 (loop closure 미탐지) | `rtabmap-databaseViewer`의 Graph View로 그래프 확인 |
| 벽이 어긋나 보임 | 누적 드리프트가 loop closure로 보정되지 않음 | Constraint View에서 loop closure 엣지 개수 확인 |
| 매핑 중 갑자기 위치가 튐 | 잘못된(false positive) loop closure | `RGBD/OptimizeMaxError` 임계값 점검 |
| 특정 구간에서 지도 생성이 멈춤 | ICP 매칭 실패 (특징 없는 벽) 또는 CPU 병목 | `ros2 topic hz`로 처리 주기 측정 |
