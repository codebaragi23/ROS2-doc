# C1. 개요와 학술적 정의

> Relocalization 심화 (Part C) 시리즈
> 이전 문서: B8. Relocalization은 Nav2 파이프라인의 어디에 위치하는가

## 1. 개요

이 문서부터 C6까지는 업로드된 `relocalization_strategy_guide.md`(다른 agent 작성)를 검토하고, Nav2·RTAB-Map 공식 문서로 보강한 최종본이다. C1은 relocalization을 학술적으로 어떻게 정의하는지 먼저 정리해, 이후 C2의 5단계 트리거 분류가 어디에 대응하는지 짚을 기준을 만든다.

## 2. 핵심 개념: Kidnapped Robot Problem과 2단계 구조

로보틱스 문헌에서 relocalization은 보통 **Kidnapped Robot Problem(KRP)**이라는 이름으로 다뤄진다: "로봇이 사전 위치 정보 없이(또는 위치 추정이 완전히 틀어진 채) 이미 알고 있는 지도 안에서 자신의 위치를 다시 찾아야 하는 문제."

관련 연구들은 이 과정을 보통 두 단계로 나눈다.

1. **Global Relocalization(사전 정보 없이 전역 재탐색)**: 사전 정보 없이(또는 매우 부정확한 정보로) 지도 전체에서 후보 위치들을 찾아 하나로 좁혀가는 단계. "Place Recognition"이라고도 불린다.
2. **Pose Tracking / Refinement(위치 추적·정제)**: 일단 대략적인 위치를 찾은 뒤, 센서 데이터로 계속 위치를 정밀하게 추적·보정하는 단계. 평상시 로봇이 잘 움직이고 있을 때 하는 일이 바로 이것이다.

이 구분이 중요한 이유: **평소의 RTAB-Map localization(잘 동작할 때)은 이미 2단계(추적)에 있는 것이고, 원문에서 다루는 "긴급 relocalization" 상황은 1단계(전역 relocalization)로 강제로 되돌아가야 하는 상황**이다. 이 둘은 필요한 대응이 다르다 — 평소 추적 상태의 미세 보정과, 완전히 위치를 잃은 상태에서의 재탐색은 다른 문제다.

## 3. 이 프로젝트에서의 적용 (Yahboom X3)

RTAB-Map은 이 2단계 구조를 명시적인 "모드"로 나누지는 않지만, 다음과 같이 대응된다.

- **2단계(추적)**: `Mem/IncrementalMemory=false`(로컬라이제이션 모드)에서 매 프레임 진행되는 정상적인 loop closure 매칭. B2에서 다룬 평상시 `map→odom` 갱신이 이것이다.
- **1단계(전역 relocalization)**: 매칭 포인트(inlier)가 급격히 부족해지거나 tracking이 끊겼을 때, RTAB-Map이 저장된 그래프 전체를 다시 훑어 후보를 찾는 상황. 이 프로젝트에서는 이를 자동으로 유도하기 위해 Spin Recovery(B6) 같은 물리적 동작을 함께 쓴다.

AMCL은 이 두 단계를 파티클 필터로 통합해서 처리하고(분산된 파티클=전역 탐색, 수렴된 파티클=추적), Nav2의 `reinitialize_global_localization` 서비스는 파티클을 다시 흩뿌려 1단계로 강제 복귀시키는 것과 같다. RTAB-Map에는 이런 통합된 단일 메커니즘이 없고, 원문의 5단계 분류(C2)는 사실상 **"언제 1단계로 되돌아가야 하는지를 프로젝트가 직접 규칙으로 정의한 것"**이라 이해하면 된다.

## 4. 관련 개념 정리

| 용어 | 정의 |
|---|---|
| Kidnapped Robot Problem | 사전 위치 정보 없이/틀어진 채로 지도 내 위치를 다시 찾아야 하는 문제 |
| Global Relocalization | 사전 정보 없이 지도 전체에서 위치 후보를 찾는 단계 |
| Pose Tracking/Refinement | 대략적 위치를 찾은 뒤 센서로 계속 정밀 추적하는 단계 |
| Place Recognition | Global Relocalization과 거의 동의어로 쓰이는 용어 — "지금 보는 장면이 지도의 어디인가"를 인식하는 것 |

## 5. 진단 관점

로봇이 위치를 잃었다는 보고를 받으면, 먼저 이것이 **완전한 유실(1단계 필요)**인지 **일시적 흔들림(2단계 안에서의 노이즈)**인지 구분한다.

- 완전한 유실: `map→odom` TF가 아예 갱신을 멈췄거나, RTAB-Map 로그에 `Tracking Lost` 또는 inlier 수가 0에 가까운 경고가 반복됨.
- 일시적 흔들림: TF는 계속 갱신되지만 값이 조금씩 튀는 정도. 이 경우 C4(Pose Jump 제어)가 더 적합한 대응이다.
